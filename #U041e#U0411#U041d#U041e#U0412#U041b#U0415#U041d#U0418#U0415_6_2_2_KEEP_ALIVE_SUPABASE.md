# MAVIS Task Tracker 6.2.2 — бесплатный keep-alive Supabase

## Что изменено

Добавлен адрес `/api/db-ping`. Он делает реальный безопасный запрос чтения к таблице `projects` в Supabase и возвращает `200`, если база доступна. Если Supabase недоступен или снова поставлен на паузу, адрес возвращает `503`.

Запрос не создаёт, не изменяет и не удаляет данные. SQL для обновления не нужен.

## Что сделать

1. Сначала возобновите (Resume) проект **Mavis Task Tracker** в Supabase и дождитесь статуса Active/Healthy.
2. Распакуйте архив 6.2.2 и загрузите его содержимое в правильный GitHub-репозиторий Task Tracker.
3. Дождитесь успешного автодеплоя Render либо выполните Manual Deploy.
4. Переменные Render оставьте прежними: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VIBECODE_API_KEY`. Новые секреты не нужны.
5. Откройте `https://ВАШ-СЕРВИС.onrender.com/api/db-ping`. Ожидаемый ответ содержит `"ok": true`, `"database": "supabase"`, `"version": "6.2.2"`.
6. В UptimeRobot отредактируйте монитор Task Tracker: вместо главной страницы укажите `https://ВАШ-СЕРВИС.onrender.com/api/db-ping`. Тогда один монитор одновременно проверяет Render и делает реальный запрос к Supabase.
7. Оставьте тип монитора HTTP(s). Если UptimeRobot позволяет выбрать интервал, частого запроса не требуется; главное — чтобы запрос происходил регулярно.

## Важно

- Не запускайте SQL для этой версии.
- Не меняйте и не удаляйте существующий проект Supabase.
- Не вставляйте service-role/secret key в Render для этого механизма. Используется существующий anon key.
- Endpoint кеширует результат примерно на 4 минуты, поэтому случайные частые обращения не создадут лавину запросов к базе.
- Это снижает риск автоматической паузы Free-проекта за низкую активность, но Supabase официально гарантирует отсутствие паузы за неактивность только на платном плане.
