# MAVIS Task Tracker 6.2.4 — импорт стратегического бэклога и фактическое время

## Что добавлено

1. Импортировано по SQL 85 задач из файла `подготовка (1).xlsx`, лист `Дорожная карта`.
2. Задачи распределяются по 4 проектам:
   - 1. Клиентский контур
   - 2. Команда
   - 3. Эффективность сотрудников
   - 4. Перелидоз
3. Все импортированные задачи создаются сразу в Бэклоге.
4. Если проект с таким названием уже существует — он используется и его статус Бэклога не меняется.
5. Если проекта нет — он создаётся и сразу помещается в Бэклог.
6. Ответственный переносится только там, где он указан в исходной таблице. Пустые значения остаются пустыми.
7. Дедлайн переносится только там, где он указан. Точные Excel-даты сохраняются. Если срок задан месяцем/кварталом, в дату ставится последний календарный день указанного периода, а исходная формулировка сохраняется в комментарии.
8. Задачи теперь могут быть без ответственного и без точного дедлайна.
9. При переводе задачи в статус `Готово` появляется обязательное окно `Фактически потрачено, часов`.
10. Массово закрыть задачи нельзя — время нужно указать отдельно по каждой задаче.
11. В карточке задачи показываются плановые часы и фактические часы.
12. В разделе `Команда` по сотруднику показывается суммарное фактическое время по закрытым задачам.

## Порядок обновления

### Шаг 1. Supabase

Открыть Supabase → SQL Editor → New query.

Выполнить файл:

`ОДИН_SQL_6_2_4_ВРЕМЯ_И_ИМПОРТ_85_ЗАДАЧ_В_БЭКЛОГ.sql`

SQL ничего не удаляет. Повторный запуск не должен дублировать импортированные задачи.

В контрольном результате ожидается:

- `imported_backlog_tasks = 85`
- `with_owner = 42`
- `with_deadline = 43`
- `without_owner = 43`
- `without_deadline = 42`

### Шаг 2. GitHub / Render

Заменить файлы проекта содержимым архива версии 6.2.4.

Дождаться нового Deploy на Render. Если он не начался автоматически: `Manual Deploy → Deploy latest commit`.

### Шаг 3. Проверка

1. Открыть вкладку `Бэклог` — должны быть задачи дорожной карты по четырём проектам.
2. Открыть задачу без ответственного/срока — поля должны отображаться как незаполненные, а не подставлять Сашу/сегодняшнюю дату.
3. Любую тестовую задачу перевести в `Готово` — должно появиться обязательное окно фактического времени.
4. Ввести, например, `1.5` → задача закроется, в карточке появится `факт 1.5 ч`.
5. В `Команда` фактические часы сотрудника должны увеличиться.
