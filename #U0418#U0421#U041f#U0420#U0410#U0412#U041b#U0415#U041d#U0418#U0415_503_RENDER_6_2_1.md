# MAVIS Task Tracker 6.2.1 — исправление 503 Render

## Что было не так
В версии 6.2 Render проверял здоровье сервиса по `/api/ai/health`. Этот endpoint зависит от внешнего Bitrix VibeCode API. Если внешний AI API временно отвечал ошибкой или не успевал ответить, Render считал всё приложение нездоровым и мог перестать направлять к нему трафик.

## Что изменено
- Добавлен локальный endpoint `/healthz`, который проверяет только работу Node-сервера.
- `render.yaml` теперь использует `healthCheckPath: /healthz`.
- `/api/ai/health` сохранён только для отображения статуса AI внутри приложения.
- Supabase, проекты, задачи и данные не меняются. SQL не нужен.

## Обновление
1. Распаковать архив 6.2.1.
2. Загрузить содержимое в корень текущего GitHub-репозитория приложения с заменой файлов.
3. Commit changes.
4. Render → Manual Deploy → Clear build cache & deploy.
5. Дождаться Live.
6. Проверить `/healthz`: должен вернуть JSON с `ok: true`.
7. Затем открыть приложение и проверить вход.

## Важно
Не используйте `/api/ai/health` как Render Health Check Path. Этот endpoint специально может возвращать ошибку, если проблема только у AI-провайдера; это не должно выключать весь дашборд.
